# Agent memory

Shared, public notes for coding agents (and humans) working on this fork:
working rules and lessons learned that aren't obvious from the code. Keep it
short, keep it current, and keep it **public-safe**: no personal names, email
addresses, local user paths, machine details or private project names. Those
stay in your agent's private memory.

Read with: [AGENTS.md](AGENTS.md) (entry point), [CUSTOM_BUILD.md](CUSTOM_BUILD.md)
(sync, build, release runbook), [PATHTRACER_TESTING.md](PATHTRACER_TESTING.md)
(path tracer work).

## Working rules

- **Branches.** New work goes on `dev` first. `nvidia-pt-dlss` (published as
  `nvidia-dlss-physx`) only gets tested work: build plus smoke tests passing,
  and the maintainer's OK. After publishing, fast-forward `dev` and push both.
- **Path tracer work goes on `dev-pt`**, so `dev` stays clean. Merge it into
  `dev` only when a step is finished and tested. Merge `dev` into `dev-pt`
  after every sync.
- **Never push to `origin`** (NVIDIA-RTX). Publish only through the `fork` remote.
- **The fork is public.** Before every push, check tracked files for private
  paths and private project names (`git grep`).
- **One step at a time** for larger efforts: finish a step, record it in the
  matching `.md` file, then stop for review.
- **Keep the `.md` notes current** (this file, the step tables, the findings
  logs) in the same commit as the change they describe.

## Build

- Setup, build, smoke test, DDGI test and release scripts are in `devtools/`
  (see devtools/README.md). `devtools/setup/setup_dev_windows.ps1` writes the
  PhysX/Blast/Flow SDK paths into `custom.py` (untracked), which SCons reads,
  so builds need no SDK arguments. Put new helper scripts there, not in a
  scratch folder, and keep them free of machine-specific paths.
- `scons` isn't on PATH on the maintainer's machine; use `python -m SCons`.
  Pass `-j10` (the maintainer's preferred job count).
- Stay on one flag set between builds (for example always `production=yes`).
  Switching flags recompiles nearly everything.
- `Access is denied` at link time means the editor in `bin\` is still running.
  Ask the user to close it; never kill their process.
- `.glsl.gen.h` files are generated by the build and are not tracked.
- When patching source files from a script, watch escape sequences: a `\n`
  meant for a C++ string can turn into a real newline (it happened twice, and
  the build failed with `C2001: newline in string literal`). Put longer patch
  scripts in a file instead of a shell heredoc; heredocs with quotes broke.
- Never write source files with Windows PowerShell 5.1 `Set-Content -Encoding
  utf8`: it adds a BOM, and a BOM in a `.glsl` include made the editor crash
  at startup (exit code 116).

## Class reference

- Every fork class, property, method, constant and project setting needs a
  description in `doc/classes/` or `modules/godot_physx/doc_classes/`; the
  editor's help and inspector tooltips come from there.
- Update with `bin\godot...console.exe --headless --doctool .`, then check
  the diff: it deletes docs of classes this build doesn't compile in (restore
  them) and touches unrelated upstream files (revert those). PhysX classes
  must be listed in `modules/godot_physx/config.py` `get_doc_classes()`, or
  their docs land in `doc/classes/`; that list is compiled in, so rebuild
  before running doctool again.
- Validate with `python doc/tools/make_rst.py --dry-run doc/classes modules/ platform/`.

## Releases

- Public zips must **not** contain NVIDIA Streamline/DLSS/Reflex runtime DLLs
  (NVIDIA's license). `PhysXGpu_64.dll`, the Blast and Flow DLLs and the D3D12
  Agility SDK DLLs are fine.
- Every release includes Blast and Flow: build with `blast_sdk=` and
  `flow_sdk=`. The packaging script refuses to run without their DLLs.
  The packaging script's default is the public package.
- Naming (details in CUSTOM_BUILD.md, "Versioning"): own version in
  `CUSTOM_VERSION`; tag `godot<base>-nvidia-rt-dlss-physx-v<own>`; title
  `Godot NVIDIA + PhysX (Godot <base>) v<own>`; zip
  `godot_<major>.<minor>-nvidia-rt-dlss-physx_v<own>-editor_windows_amd64[_mono].zip`.
  Git tags can't contain spaces, `+` or brackets.
- Editor zips keep the files at the zip root, with no wrapping folder. Never
  zip with `tar -C <dir> .`: its `./` prefix shows up as a folder named `.`
  and confused users (0.5.1, 0.5.2). Check the entry names before uploading.
- Rebuild right before packaging, so the version stamp (`--version`) matches
  the tagged commit, and tag that commit.
- `gh release create --target` needs the full commit SHA; a short SHA fails
  with `Release.target_commitish is invalid`.

## Path tracer

- Needs Forward+ **and** the Vulkan driver. The D3D12 driver's ray tracing is
  all stubs (upstream too). New projects default to Vulkan in this fork.
- `--rendering-driver vulkan` forces Vulkan for a project that sets D3D12.
- Test scene, supported features, bug list and step plan: PATHTRACER_TESTING.md.
- StandardMaterial3D goes through hit group 0 (`materials[]` buffer filled in
  `render_raytracing.cpp`); custom ShaderMaterials get their own hit groups.
  BaseMaterial3D stores every parameter but declares a uniform only when its
  feature is on, so check `ShaderData::uniforms` before trusting a parameter.
- Direct light (NEE) samples one light per hit, chosen by
  `lights_selection_weight()` (RIS). Any change to that weight must stay > 0
  wherever the light can contribute, or the image gets biased (too dark).
- To isolate a lighting bug, cut the scene down first (the test project's
  `--sun_only`, a single view) before reading shader code.
- Emissive StandardMaterial3D meshes are mesh lights (binding 33). Emission is
  counted once: by NEE at rough vertices (payload bit 27 tells the next hit to
  skip flagged geometry), by the BRDF ray otherwise. Keep both sides in sync.
- To check a sampling change for bias, compare mean **linear** brightness
  against a reference build at higher spp, with `--linear` and a low exposure.
  Means of tonemapped 8-bit images look darker the noisier they are.
- Custom hit groups compile asynchronously; their surfaces are skipped until
  ready. After shader template changes, screenshot after 300-400 frames, or
  custom-shader objects are simply missing.
- Runtime-generated RT shaders (hit groups, `raytracing_vertex_displace.glsl`)
  are ShaderRD templates: `version_build_variant_stage_sources()` gives the
  expanded source, then placeholders are replaced and it is compiled with
  `shader_compile_spirv_from_source()`. Compute can't use `gl_PrimitiveID`.
- Path traced volumetric fog reuses Godot's camera-space integrated froxel
  `VolumetricFog::fog_map`, so sample it only for primary rays. Before updating
  volumetric fog in the PT render path, run voxel GI setup so
  `rbgi->voxel_gi_textures[]` contains default textures; otherwise binding 13
  in `volumetric_fog_process.glsl` is empty and fog compute dispatch fails.
  Sky misses must also apply `volumetric_fog_sky_affect` with the same legacy /
  non-legacy blend formula as `shaders/environment/sky.glsl`.
- Async RT pipeline build tasks own newly compiled per-hit-group shader RIDs
  until finalized into a `PipelineBundle`. If shutdown abandons a finished task,
  free those task-owned shaders as well as the new pipeline, or exit reports
  leaked `Shader` RIDs.
- Alpha blended and refractive StandardMaterial3D surfaces are traced
  (`ShaderData::rt_traces_transparency()`); everything else in the alpha
  pass stays a raster overlay. Stochastic opacity is decided in any hit from
  a hash of the payload's `rng_state` and the triangle, never by advancing
  the RNG there: any hit can run more than once per triangle.
- A BLAS dies with the buffers it was built from. Check
  `RenderingDevice::acceleration_structure_is_valid()` before freeing one from
  a cache. Don't bind buffers you free later through a linear-pool uniform
  set; use a persistent set (freed with the buffer).

## DDGI

- Notes, test project and findings: DDGI.md. Work on `dev-ddgi`.
- Measure flicker before guessing: the test project's `--measure` with
  `--stdmap` (where) and `--trace_px` (how it moves over time). The probe
  RNG is deterministic, so a spike repeats at the same frame in every run.
- Any rule that adapts the blend weight to the sampled value (like "lower
  the hysteresis when the light changed") biases the result and turns ray
  noise into flicker. Require the change to stand out of the noise and to
  repeat before acting on it.
- Code that renders extra frames with `RenderingServer::draw()` inside one
  main loop iteration (baking, previews) must not break per-frame state:
  the Streamline frame token advances once per iteration, so DLSS gets a
  new token when its constants were already set for the current one.
- Opening a test project in the editor rewrites its `project.godot` (drops
  values equal to the defaults) and adds `.uid` files: revert those.
- A change signal for the probes must be exact, not just "less noisy": the
  fixed rays' light still flickers between updates (soft shadows), but their
  hit distance only changes when geometry moves. Check every new adaptive
  rule against the static interior flicker test (0.00-0.03% budgeted).
- `DDGIProbe` (ddgi_inc.glsl) and `DDGIProbeGPU` (render_ddgi.h) must match;
  a static_assert checks the size. The schedule pass resets fields on
  scroll/reset; the relocate pass only writes what it owns.
- Probe ray directions must be reproducible: the trace and both blends of a
  frame have to compute the same direction for a ray. State they depend on
  (the guide) is written by the blend as `guide_next` and committed in the
  relocate pass, after both blends.
- Papers from KIT and others often ship GPL code (Markov chain path guiding:
  GPLv3; A-SVGF code: unclear). This fork is MIT: implement from the paper,
  never copy that code (same rule as the RTXGI SDK).
- Measure GPU cost with the test project's `--gpu-profile ... --bench=300`
  before and after; per pass times are in the BENCH line. Before optimizing
  a pass, switch parts of it off in a test build to see what costs: the
  probe lookup in the probe rays' closest hit was 70% of the trace. GPU
  times shown during `--write-movie` runs are meaningless (30-80 ms).
- Texture-heavy work in ray tracing hit shaders runs at low occupancy. Write
  what it needs per ray into a buffer and do it in a compute pass after the
  trace (DDGI bounce light: 5.1 ms of trace became 1.5 + 1.3 ms).
- Custom-shader hit groups compile for seconds. Anything that classifies or
  caches against the TLAS (DDGI probe states) must not run against a scene
  with those surfaces missing; they are now traced with the default hit
  group meanwhile. To see what the TLAS holds, render the path tracer
  (`pathtracing_enabled`, debug mode geometry normals) from a test script.
- Before changing what "no usable probe" means, check the probe states
  view (debug mode 4) in a real scene: a sampler change can turn a hidden
  classification problem into black surfaces.
- Compare DDGI with the path tracer at a fixed exposure (auto exposure off,
  same multiplier) and split the light by turning sources off one at a time
  (reflections, sky, sun, bounce energy). With auto exposure the noisy path
  tracer image and the smooth DDGI image get different exposures.

## Ambient occlusion (XeGTAO)

- XeGTAO (`effects/xegtao.*`, `shaders/effects/xegtao_*.glsl`) is ported
  from Intel's MIT code; keep the notice in COPYRIGHT.txt when adding
  files. Its view space is x right, y up, z forward: Godot normals and bent
  normals get z negated at the boundary.
- It produces the texture the scene shader already reads as SSAO (binding
  27, `SCREEN_SPACE_EFFECTS_FLAGS_USE_SSAO`), so AO is applied once, to
  ambient light only. Never add a second AO multiplication.
- `RD::capture_timestamp()` (`RENDER_TIMESTAMP`) fails inside a compute
  list that already dispatched: give every timed pass its own list.
- The material storage's default samplers carry the mipmap LOD bias (TAA
  and upscalers lower it), and Vulkan adds it to explicit `textureLod()`
  levels too. Passes that pick depth MIPs need their own sampler.
- `--gpu-validation` only validates when the Khronos validation layer is
  installed (Vulkan SDK). Check the log for `VK_LAYER_KHRONOS_validation`
  before reporting a clean validation run.
